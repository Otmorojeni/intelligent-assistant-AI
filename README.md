**DoCorp** — это защищённая корпоративная нейро-символьная система для автоматизации документационного обеспечения управления (ДОУ). Сервис объединяет экспертный семантический поиск по нормативной базе (**Инструкция № ОД-184**, **Матрица визирования**, **Методические рекомендации**), диалоговую сборку проектов документов (**7 модульных шаблонов УТВ-01..УТВ-07**), автоматический нормоконтроль черновиков `.docx` с функцией **Auto-Fix**, детерминированный расчет маршрутов согласования и горячее версионирование регламентов (`Hot-Reload`) в закрытом контуре организации.

### Метрики быстродействия и ресурсов:

* **0 МБ накладных расходов на Node.js:** статический бандл React SPA скомпилирован в `ui/` и раздается напрямую ядром FastAPI.
* **Скорость отклика:**
  * Семантический поиск по нормативной базе: **`< 400 мс`**.
  * Расчет матрицы визирования (13 правил): **`< 30 мс`**.
  * Нормоконтроль черновика `.docx`: **`< 50 мс`**.
  * Генерация модульного документа: **`< 120 мс`**.
  * `Zero-Hallucination Guard`: **`< 30 мс`** (блокировка нерелевантного запроса до вызова LLM).

## 4. Работа с LLM: локальная Ollama (qwen2.5:1.5b) и автономный фоллбэк

1. **Модель нейросети:**
   Система использует компактную и быструю языковую модель **`qwen2.5:1.5b`** (Q4_K_M квантование), потребляющую всего ~1.15 ГБ ОЗУ и идеально подходящую для CPU-инференса без графических ускорителей:
   ```bash
   ollama pull qwen2.5:1.5b
   ```
2. **Сетевой шлюз Docker $\leftrightarrow$ Хост:**
   В `docker-compose.yml` настроен сетевой мост `host.docker.internal:host-gateway`, позволяющий контейнеру приложения бесшовно обращаться к локальной службе Ollama хоста по адресу `http://host.docker.internal:11434/v1`.
3. **Автономный оффлайн-фоллбэк (100% отказ устойчивость):**
   Если Ollama недоступна или перегружена, **сервис не зависает и не возвращает ошибку 500**. Включается встроенный детерминированный синтезатор ответов: формируется лаконичная выжимка напрямую из найденных релевантных пунктов ОД-184 с сохранением ссылок на регламент. Нормоконтроль, конструктор документов и расчет матрицы работают на 100% автономно без LLM.

## 5. Функциональные модули системы

### 5.1. ИИ-Консультант ДОУ (RAG без галлюцинаций, ссылки на пункты ОД-184)
* **Гибридный ретривер:** объединяет полнотекстовый поиск PostgreSQL (`tsvector`), ранжирование BM25Okapi, посимвольные n-gram и стемминг косинусных векторов через алгоритм RRF (Reciprocal Rank Fusion) со специализированным словарем синонимов ДОУ.
* **Лаконичные экспертные ответы:** 1–2 предложения прямого ответа, до 3 структурированных требований регламента и обязательное указание точного пункта и страницы Инструкции № ОД-184.
* **Zero-Hallucination Guard:** если максимальная релевантность найденных пунктов составляет менее 25%, запрос блокируется за 30 мс с регламентированным вежливым ответом об отсутствии информации в нормативной базе.
* **Встроенный глоссарий:** автоматическое распознавание отраслевых сокращений (МЭДО, ИОД, ИИС ДО, ЛНА, ПД).

### 5.2. Конструктор модульных документов (УТВ-01..УТВ-07) и автозаполнение
* **7 официальных модульных типов:**
  * УТВ-01: Приказ о вводе в эксплуатацию информационной системы
  * УТВ-02: Приказ о назначении ответственных за делопроизводство
  * УТВ-03: Приказ о приеме и передаче дел и имущества
  * УТВ-04: Приказ об утверждении и введении в действие ЛНА
  * УТВ-05: Распоряжение о проведении внутреннего аудита процессов
  * УТВ-06: Распоряжение о создании проектного комитета
  * УТВ-07: Распоряжение о создании рабочей группы
* **Строгое соответствие Разделу 3.3:**
  * Автоматическое удаление квадратных скобок и сносок вида `[1]`, `[7]`.
  * Удаление служебных надписей («МОДУЛЬНЫЙ ДОКУМЕНТ», примечания, линии `____`).
  * Сохранение элементов с пометкой `НЕ УДАЛЯТЬ` (визуализация ЭП, грифы утверждения).
  * Формирование отметки п. 2.3 для регистрации проекта документа.
* **Диалоговый Slot-Filling:** интерактивное заполнение полей проекта документа прямо в окне чата с ассистентом.

### 5.3. Автоматический нормоконтроль черновиков .docx и функция Auto-Fix
* **10 правил контроля (`CHK-01..CHK-10`):**
  * Поля страницы по п. 5.1 ОД-184 (левое не менее 30 мм, правое не менее 15 мм, верхнее/нижнее 20 мм).
  * Гарнитура шрифта и кегль (12–14 pt, Times New Roman / Arial / PT Astra Serif).
  * Межстрочный интервал (1.0–1.5) и абзацный отступ (1.25 см по п. 5.3).
  * Корректность оформления заголовка («О ...» / «Об ...» без точки и подчеркивания).
  * Полнота реквизитов подписи (должность, подпись/ЭП, инициалы и фамилия).
  * Проверка на не удаленные служебные артефакты шаблонов.
* **Инновационная функция Auto-Fix:** сервис не просто находит ошибки, а **в 1 клик генерирует исправленный документ `.docx`**, приводя поля, шрифты, интервалы и реквизиты к идеальному нормативному виду.

### 5.4. Калькулятор матрицы согласования (13 правил, автосинхронизация)
* **Полный охват:** все 13 правил Приложения 2 к Инструкции № ОД-184.
* **Интуитивный UI:** выпадающий список правил с адаптивным позиционированием, фильтрацией по категориям (Приказы, Распоряжения, Письма), живым поиском и автоматической синхронизацией параметров калькулятора при выборе правила.

### 5.5. Горячее версионирование (Hot-Reload) и управление документами
* **Обновление без даунтайма:** загрузка новой редакции регламента v2.0 (.pdf/.docx) автоматически архивирует старую (`is_active = false`) и выполняет моментальную переиндексацию чанков на лету.
* **Управление жизненным циклом:** откат к архивной версии в 1 клик («Включить») и удаление ошибочных документов через UI и защищенный эндпоинт `DELETE /v1/documents/{doc_code}`.

### 5.6. Информационная безопасность, RBAC (4 роли) и защита данных
* **Минималистичная авторизация:** центрированная плашка входа по защищенному протоколу JWT (`demo` / `demo`, `admin` / `cdo-admin-2026`).
* **Ролевая модель:**
  1. `employee` (Сотрудник): базовые консультации, нормоконтроль черновиков, конструктор документов.
  2. `dou_specialist` (Специалист ДОУ): расширенный доступ к нормоконтролю, выгрузка отчетов.
  3. `security_auditor` (Служба безопасности): просмотр полного журнала аудита событий.
  4. `admin` (Администратор): управление редакциями регламентов, Hot-Reload, удаление версий.
* **Защита информации:** фильтрация выдачи по грифам доступа (ДСП, Конфиденциально), блокировка `Prompt Injection` и журнал аудита всех действий пользователей.

## 7. Справочник REST и SSE API

| Метод | Эндпоинт | Назначение | Доступ |
| :--- | :--- | :--- | :--- |
| `POST` | `/v1/auth/token` | Выдача JWT-токена доступа | Публичный |
